# ADR-0009. Триггеры модулей SoupVisuals без миксинов

- Статус: **принято**
- Дата: 2026-11-15
- Связано: ADR-0002 (render adapter), `docs/port/soupvisuals.md`
- Контекст: перенос второй партии модулей SoupVisuals на 1.21.10

## Контекст

Оригинал висит на 40 миксинах. Четыре из них — единственный способ, которым модули узнают
о событиях игрока:

| Миксин оригинала | Что он даёт | Модули |
|---|---|---|
| `ClientPlayerEntityMixin` (прыжок) | приватное поле `jumping` | JumpCircles |
| `ClientPlayerEntityMixin` (тотем) | смена стека в руке | TotemParticles, KillEffect |
| `ClientPlayerEntityMixin` (атака) | `attack()` игрока | KillEffect, HitSounds |
| `HeldItemRendererMixin` | `renderFirstPersonItem` | HandTweaks |

`AGENTS.md` запрещает добавлять миксины без ADR, а Fabric API 1.21.10 не даёт публичного
доступа ни к `jumping`, ни к `HeldItemRendererEvent`. Значит нужен либо ADR с миксинами, либо
эквивалентные триггеры на публичных событиях. Второй путь выбран сознательно: он не ломает
сборку и не требует согласования точек инъекции, а расхождение с оригиналом локально
(только момент старта анимации).

## Решение

Триггеры живут в `silkvis/client/SoupVisualsClient.java`, модули остаются чистыми:

| Событие оригинала | Порт | Задержка/расхождение |
|---|---|---|
| `jumping` (прыжок) | `END_CLIENT_TICK`: `onGround` сменился с `true` на `false` | нет; то же самое нажатие |
| смена стека в руке | `END_CLIENT_TICK`: в руке был `TOTEM_OF_UNDYING` и пропал (или `getCount()` уменьшился) | нет |
| `attack()` игрока | `AttackEntityCallback.EVENT` (Fabric API, вызывается из `ClientPlayerInteractionManager.attackEntity`) | нет |
| `renderFirstPersonItem` | **не портирован**: Hook отсутствует, HandTweaks работает только настройками | см. ADR-0010 |

Правила, которые нельзя потерять при замене:

1. **Прыжок** — переход `onGround`, а не `isOnGround()==false`: иначе круги появлялись бы
   каждый тик падения. При `wasOnGround=false` состояние просто запоминается.
2. **Тотем** — потеря тотема в основной руке считается попапом независимо от причины
   (смерть, `use`, выбрасывание). Оригинал ловит именно смену стека, поэтому расхождения
   нет; ложное срабатывание при выбрасывании тотема было и в оригинале.
3. **Атака** — колбэк вызывается на клиенте до отправки пакета, поэтому `hitPoint` берётся
   из `EntityHitResult` колбэка, а не из `ProjectileUtil.raycast` отдельно. Это же даёт
   дальность и точку попадания без второго рейкаста.
4. Все триггеры только для `MinecraftClient.player != null` и того же мира;
   `resetOnWorldChange` чистит состояние.

## Последствия

- Нет новых миксинов; сборка остаётся на публичном Fabric API.
- HandTweaks без хука: настройки сохраняются и читаются, но не влияют на рендер
  (см. ADR-0010). Это единственное известное функциональное расхождение второй партии.
- При появлении в Fabric API `HeldItemRenderer`-события или публичного `jumping`
  HandTweaks/JumpCircles переключаются на него без изменения самих модулей.
