# ADR-0004 — Конфигурация, атомарная запись и локальный JSON

- Статус: принято
- Дата: 2026-11-12

## Контекст

CFG-01..CFG-04 требуют JSON со `schemaVersion`, атомарную запись, backup последней
исправной версии, сохранение повреждённого файла и безопасный fallback. Внешняя
JSON-библиотека увеличила бы поверхность зависимостей и усложнила бы автономные тесты.

## Решение

1. Собственный минимальный JSON (`silkvis.config.json`): строгий RFC 8259-парсер,
   лимит вложенности 64, лимит размера 16 MiB, детерминированный writer.
   Это снимает зависимость от Gson на уровне ядра и позволяет прогонять self-checks
   на чистом JDK.
2. `JsonConfigFile<T>` (общий для global.json, ui.json, destinations.json,
   markers.json, automation.json):
   `validate → temp file → fsync/atomic move`, backup `.bak` перед заменой.
3. Ошибка разбора/валидации: копия `*.corrupt-<timestamp>` сохраняется, загружаются
   безопасные defaults со статусом `SAFE_DEFAULT`; исходный файл не перезаписывается
   молча.
4. `schemaVersion` из будущего → `READ_ONLY_NEWER`, файл не перезаписывается.
5. Debounce 500 ms для UI-правок, явный Apply/flush перед выходом (`Debouncer`).
6. Числа валидируются на finite/range, id — на registry-формат, лимиты хранятся как
   `OptionalLimit(enabled, value)`; `-1` как «бесконечно» запрещён.

## Последствия

- Нет внешней зависимости для конфигов; всё тестируется на JDK без сети.
- Формат дампа детерминирован (стабильный порядок ключей) — удобно для диффов.
- При появлении сложных схем потребуется отдельная валидация; до этого правила
  живут в `ConfigCodec.validate()` и `Validators`.
