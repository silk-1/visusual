# ADR-0006. Внешние интеграции: Xaero's Minimap (XaeroLib) и Seed Map / Better HUD Widgets

- Статус: **вытеснено** ADR-0007 в части выбора внешней карты (выбрана AtlasMap);
  Xaero/Seed Map остаются как история вопроса
- Дата: 2026-11-12
- Контекст: решение владельца проекта, разрешения авторов сторонних модов

## Контекст

Владелец проекта получил от авторов двух модов явное разрешение на интеграцию:

1. **Xaero's Minimap** — автор подтвердил, что **XaeroLib** предназначен для разработчиков
   и допускает встраивание карты.
2. **Seed Map [1.20.1] / Better HUD Widgets** — авторы также дали разрешение.

Собственная реализация карты в SilkVis сейчас доходит только до заглушки: тайлы
семплируются в `ClientTileSampler`, но GPU-путь отрисовки не сделан
(`docs/known-limitations.md`). Писать свой движок карт с нуля — недели; взять чужой API по
разрешению — дни. Поэтому вопрос не «хотим ли мы», а «что технически возможно».

## Решающий факт, который надо проверить первым

Цель проекта — **Minecraft 1.21.10** (`"minecraft": "=1.21.10"`). Интеграция возможна
только если у библиотеки есть сборка под 1.21.10 **и** опубликованный API (Maven-артефакт
или стабильный публичный класс), а не только jar мода.

| Библиотека | Что нужно проверить | Если нет |
|---|---|---|
| XaeroLib | есть ли релиз под 1.21.10; координаты артефакта (Maven) либо публичный API-класс; лицензия на linking | интеграция откладывается, карта остаётся своей |
| Seed Map / Better HUD Widgets | версия игры в названии «[1.20.1]» — вероятно, только 1.20.1; есть ли 1.21.10 | берём только **идею** (какие данные показывать), код не берём |

**Разрешение автора — это не техническая совместимость.** Мод на 1.20.1 нельзя
подключить к 1.21.10: изменились mappings и внутренние API.

## Решение

1. Любая внешняя интеграция — **мягкая и необязательная**:
   - `fabric.mod.json` → `suggests`, никогда `depends`;
   - отсутствие библиотеки не ломает SilkVis, а даёт модулю состояние
     `CAPABILITY_UNSUPPORTED` с причиной `lib_missing` в UI (уже существующий механизм
     `IntegrationRegistry.probe` + reason-коды);
   - интеграция включается **выключенным по умолчанию** модулем, как остальные функции.
2. Код чужого мода **не копируется и не бандлится**. Допустимо: вызов публичного API,
   ссылка на Maven-артефакт в `compileOnly`, ссылка на их репозиторий в документации.
3. Адаптер живёт за нашим портом: `silkvis/map/MapSource` (интерфейс) →
   реализации `OwnMapSource` (наш семплер) и `XaeroMapSource` (адаптер). Рендер и HUD
   работают с портом и не знают, откуда тайлы. Это ровно тот принцип, по которому уже
   сделан `Painter`/`VanillaPainter` (ADR-0002).
4. Пока адаптера нет, `OwnMapSource` остаётся и продолжает рисовать заглушку. Никаких
   «полуживых» двух карт одновременно: источник выбирается один, в настройках.
5. Атрибуция обязательна: имя автора и ссылка на мод в экране «Интеграции» и в README.

## Последствия

- Нужны точные координаты артефакта/классов XaeroLib под 1.21.10 — без этого пункт 3
  остаётся планом, а не кодом. Запрос владельцу: скриншот списка версий мода и
  `XaeroLib` (или ссылка на их страницу) + содержимое jar, если он уже скачан.
- `IntegrationRegistry` получает новый probe `xaerolib`, `MapSource` — новый интерфейс;
  это правки в `src/main/java/silkvis/map/**` и `integration/**`.
- Seed Map / Better HUD Widgets: переносим **набор полезных данных** (координаты в Аду,
  slime-chunk, таймер сессии, реальное время, пинг), а не чужой код. Ядро этих
  вычислений — чистый Java без Minecraft, поэтому оно вынесено в отдельную задачу
  (`docs/agent-prompts/seed-hud-extras.md`).

## Что не делаем

- Не тащим Fabric API модули, которых нет под 1.21.10.
- Не подменяем ванильную карту предметов и не трогаем серверные правила.
- Не обещаем работу интеграции до первого запуска с ней.
