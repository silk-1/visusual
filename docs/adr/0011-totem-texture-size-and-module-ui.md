# ADR-0011. Тоттем в 128 px вместо 16×16 и экран модулей SoupVisuals

- Статус: **принято**
- Дата: 2026-11-15
- Связано: ADR-0009, ADR-0010, ASSET-04

## Контекст

Два замечания по одной сборке:

1. Свой тотем «нечёткий, как будто там 16 на 16». Так и было: `TotemPackBuilder`
   жёстко писал текстуру 16×16, как у ванильного тотема, и уменьшал картинку одним
   проходом bilinear. Minecraft не требует ванильного размера: ресурспак принимает
   `totem_of_undying.png` любого размера, 16×16 — это размер *ванильного ассета*, а не
   ограничение движка.
2. «Всего визуала не видно, где меню». Модули SoupVisuals были перенесены целиком
   (данные, дефолты, рендер), но их настройки никто не читал: в интерфейсе не было ни
   списка модулей, ни переключателя, ни настроек. Включить модуль можно было только
   строкой Java в сборке.

## Решение

**Тоттем.** `TotemPackBuilder` пишет текстуру выбранного размера: 16, 32, 64 или 128
(по умолчанию 128). `VisualSettings.totemTextureSize` — новая настройка, которая
проверяется по списку допустимых значений, сохраняется в `ui.json` и **пересобирает
набор** при смене (кнопки размера на вкладке «Тотемы»). Уменьшение — пошаговое: сначала
деление вдвое, пока сторона не станет ≤2× целевой, затем один bilinear-проход; для
пиксель-арта (обе стороны кратны целевому размеру) — NEAREST без сглаживания, иначе
16×16 спрайт превращался в кашу. Лимиты подняты до 16 МиБ и 8192 px по стороне.

**Обрезка фона.** Второе замечание по тотему: «хочу, чтобы обрезался их фон». Новый шаг
`TotemPackBuilder.trimBackground` берёт цвет четырёх углов; если углы одного цвета, все
пиксели в пределах допуска (24 из 255 по каналу) становятся прозрачными, картинка
обрезается по рисунку и достраивается до квадрата по центру (без растяжения). Если углы
разные (например, фотография с градиентом), картинка не меняется. Настройка
`VisualSettings.totemTrimBackground`, по умолчанию **включена**, переключатель на вкладке
«Тотемы» рядом с размером, и она тоже пересобирает набор сразу.

**Модули.** Добавлен `SoupSettingsScreen` — экран со списком десяти перенесённых
модулей и их собственным деревом настроек (группы, булевы, числа, списки, цвета,
кнопки). Список строится из объектов модулей, поэтому новый модуль появляется на экране
без правки экрана. Экран открывается тремя путями: кнопка на вкладке VISUAL, кнопка в
панели выбранного модуля (список модулей стал рабочим — раньше клик по строке ничего не
делал) и необязательная горячая клавиша без дефолтной привязки.

Состояние и значения пишутся в `config/silkvis/soupvisuals.json`
(`SoupSettingsFile`), иначе после перезапуска всё снова выключено. Идентификатор модуля
берётся из его ключа (`module.hitbubbles.name` → `hitbubbles`); это покрыто
самопроверкой, потому что ошибка в ключе молча схлопывает десять модулей в один.

Модули зарегистрированы в `ModuleRegistry` (`soup.<id>`) настоящими переключателями:
состояние в списке и состояние модуля — одно и то же, без второй копии правды.

## Последствия

- Текстура 128 px втрое больше по файлу, чем 16 px (десятки килобайт), и грузится один
  раз при включении набора. Обмен принят: чёткость важнее размера.
- Настройка размера не влияет на уже включённый набор, пока он не пересобран; кнопка
  размера пересобирает его сразу.
- Экран настроек не Minecraft-виджеты, а собственные (`ButtonWidget`, `Caption`), как и
  остальной интерфейс мода: одинаковое поведение и одинаковые правила доступности.
- Полноценного выбора цвета нет — фиксированная палитра из восьми цветов и цикл по ней.
  Это записано в известных ограничениях; отдельный виджет — отдельная задача.
