## Раунд 4 — первая попытка запуска в игре (2026-11-12)

### Что произошло

Мод был собран (`0.1.0-p0`) и установлен в настоящий клиент. Игра **не стартовала**:

```text
Incompatible mods found!
 - Install fabric-api, version 0.138.4 or later.
 - Replace mod 'Fabric Loader' 0.19.2 with any version between 0.20.0 (inclusive) and 0.21.0 (exclusive).
   Mod 'SilkVis' (silkvis) 0.1.0-p0+mc1.21.10 requires any version between 0.20.0 (inclusive)
   and 0.21.0 (exclusive) of mod 'Fabric Loader', but only the wrong version is present: 0.19.2!
   Mod 'SilkVis' requires version 0.138.4 or later of fabric-api, which is missing!
```

Это не краш кода мода: Loader отклонил мод **до** загрузки классов, по метаданным.
То есть первый реальный прогон в игре вскрыл дефект, который не мог поймать ни `javac`,
ни `selfCheck` — неверно объявленные зависимости.

### Разбор

| Симптом | Настоящая причина | Решение |
|---|---|---|
| `requires ... 0.20.0 <0.21.0 ... but only 0.19.2` | жёсткая **верхняя** граница в `fabric.mod.json`, скопированная из dev-окружения (`loader_version=0.20.1`), а не из требований кода | `fabricloader: ">=0.19.0"`, верхней границы нет |
| `fabric-api ... is missing` | Fabric API не был установлен у игрока, а мод без него не работает (HUD, keybind, тики, события мира) | зависимость остаётся обязательной; описан порядок установки — `docs/install.md` |
| `fabric-api 0.138.4 or later` | нижняя граница взята равной версии из dev-сборки, хотя код не требует именно её | `fabric-api: ">=0.116.0"` — подходит любой билд для 1.21.10 |

Проверено по коду: из Loader API используются только `FabricLoader#getInstance`,
`isModLoaded(String)`, `getGameDir()`, `getConfigDir()` — все стабильны с 0.16, поэтому
нижняя граница 0.19.0 обоснована, а не «на глаз».

### Изменено

- `src/main/resources/fabric.mod.json` — диапазоны зависимостей: `>=0.19.0` и `>=0.116.0`,
  верхних границ нет (они отсекают будущие версии загрузчика и ничего не гарантируют);
- `gradle.properties` — `mod_version` → `0.1.1-p0`, чтобы новый jar отличался по имени;
- `docs/install.md` — новый документ: что нужно игроку, откуда скачать, порядок установки,
  проверка «мод загрузился», таблица диагностики `Incompatible mods found`;
- `README.md` — раздел «Установка в игру»;
- `docs/dependency-matrix.md` — обновлены строки 5 и 6 и добавлен риск 5 (верхние границы);
- `docs/known-limitations.md` — пункт про непроверенный запуск уточнён.

### Статус после раунда

Сборка (`clean build`, `selfCheck 60/60`) от этих правок не зависит — менялись ресурсы и
версия. **Запуск в игре по-прежнему не подтверждён**: следующий шаг — пересобрать
(`build.bat`), положить `silkvis-0.1.1-p0+mc1.21.10.jar` + `fabric-api-…+1.21.10.jar`
в `mods` и проверить `F1` / `Right Shift` / «по умолчанию ничего не нарисовано».
До этого ни один UI/HUD-статус не поднимается выше `IMPLEMENTED_NOT_TESTED`.

## Раунд 5 — первый успешный запуск в игре (2026-11-12)

### Что подтверждено скриншотами

Мод `0.1.1-p0` запущен в клиенте 1.21.10 с Fabric API. Игра стартовала, меню открылось
по **Right Shift**, в мире рисуется HUD-оверлей.

| Проверено | Наблюдение |
|---|---|
| запуск клиента | игра дошла до мира, мод загружен, краха нет |
| Right Shift | открывает окно SilkVis |
| тема | Graphite/Turquoise, акцент на выбранном элементе |
| вкладки | Визуал, HUD, Карта, Музыка, Тема, Интеграции, Настройки + «Автоматизация» с текстом «планируется на следующий этап, задачи не запускаются» |
| контролы | тумблеры (on/off с подписью), слайдер (перетаскивание, значение 4000↔5100), кнопки «Открыть редактор HUD», «Сбросить раскладку», пресет Balanced |
| локализация | весь интерфейс по-русски, кириллица рендерится корректно |
| HUD в мире | панель FPS в левом верхнем углу и миникарта-заглушка справа |
| размер окна | окно укладывается в 960×620, компактный режим (<700 scaled) включился сам |

### Дефекты, найденные по скриншотам (а не догадкам)

1. **Подсветка вкладки не следовала выбору.** Содержимое менялось, а акцентная рамка
   оставалась на вкладке, выбранной в момент последнего `init()` экрана (на скриншотах —
   «Музыка» при открытых «Настройках», «Карте», «HUD»). Причина: `ButtonWidget.Style`
   выставлялся только при сборке экрана. Исправлено: стили выводятся каждый кадр
   (`syncNavigationStyles`).
2. **FPS всегда `0 FPS 0.0 ms`.** `HudDataCollector.onFrame()` существовал, но ниоткуда не
   вызывался — счётчик кадров не работал. Исправлено: вызов из HUD-хука
   (`SilkVisClient.onFrame`), до ранних `return` рендерера.
3. **Поле поиска — пустой ящик без подсказки и без фокуса.** `TextInputWidget` получал
   `placeholderKey` и никогда его не рисовал, а `FocusManager.focus()` не вызывался по
   клику (фокус ставил только Tab). Исправлено: подсказка рисуется, клик по контролу
   передаёт ему фокус.
4. **Координаты не появились в HUD при включённом виджете.** Точная причина не доказана;
   найдена реальная хрупкость: `RateLimiter`/`FpsAggregator` считали начало отсчёта равным
   нулю, а `System.nanoTime()` имеет произвольную (в т.ч. отрицательную) точку старта —
   на такой машине 10-герцевые обновления координат не сработали бы никогда. Оба класса
   переведены на явный флаг первого вызова. Требуется повторная проверка в игре.

### Чего этот запуск не доказывает

`F1` (скрытие оверлея), сохранение настроек между перезапусками, редактор HUD,
перетаскивание виджетов, карта (тайлы, GPU), музыка/Now Playing, медиа-IPC,
точки назначения, перцентили PERF. Всё это остаётся `IMPLEMENTED_NOT_TESTED`
или `PLANNED` в матрице.

### Изменено

`client/SilkVisScreen.java`, `client/SilkVisClient.java`, `render/HudHook.java`,
`ui/widget/TextInputWidget.java`, `hud/RateLimiter.java`, `hud/FpsAggregator.java`, `mod_version` → `0.1.2-p0`
(чтобы исправленный jar отличался по имени), плюс матрица требований и
`docs/known-limitations.md`.
Синтаксис: 122/122 файлов разобраны парсером; **компиляции и повторного запуска не было**.

## Раунд 6 — визуальный проход (2026-11-12)

### Что было не так в картинке

Токены темы давно содержали `radiusPanel = 8` и `radiusControl = 4`, `spacingXs..Xl`
и `motionMs = 160`, но **радиус нигде не рисовался**: ванильный `fill` умеет только
прямоугольники, поэтому окно, панели, кнопки, тумблеры, слайдер и поле поиска выглядели
как набор плоских прямоугольников с обводкой 1 px. Иерархия была только за счёт цвета.

### Что изменено

| Область | Было | Стало |
|---|---|---|
| `ui/Painter` | `fill`, `outline` | `roundRect`/`roundPanel` — закругление строится горизонтальными пробегами (без шейдеров, без новых render-состояний; углы не смешиваются, а вырезаются, поэтому панель поверх панели сохраняет свой цвет) |
| окно | плоский прямоугольник | мягкая трёхслойная тень + закруглённая панель с обводкой |
| навигация | серая плита | карточка со скруглением, вордмарк с акцентным подчёркиванием |
| выбранная вкладка | обводка 1 px | то же, но со скруглением; фокус — внешнее кольцо, а не второе |
| раздел настроек | заголовок + линия | заголовок, подпись-описание раздела, короткое акцентное правило и волосяная линия; контент начинается ниже и попадает под clip |
| тумблер | квадрат с бегунком-квадратом | пилюля (радиус = высота/2) с круглым бегунком; состояние по-прежнему подписано текстом `on/off` (UI-01) |
| слайдер | прямоугольный трек | скруглённый трек, скруглённая заливка, бегунок-капсула, подсветка при фокусе |
| поле поиска, тултип, HUD-панели, миникарта | прямоугольники | закруглённые панели |
| миникарта без тайлов | слово `map` | локализованная строка `Нет тайлов` / `No tiles` (новый ключ `silkvis.map.no_tiles`) |

Подписи разделов — новые ключи `silkvis.tab.<tab>.hint` (RU/EN). Если ключа нет, строка
не рисуется: переводы не обязательны для работы экрана.

### Стоимость

`roundRect` — до `radius` строк по два `fill` на строку. Для окна/панелей это ~100
квадов на кадр, для HUD — до ~80. Бюджет PERF-02 (render CPU p95 ≤ 1 ms) этим не
проверяется: замера не было, поэтому в матрице PERF-* остаётся `NOT_MEASURED`.

### Не сделано и не выдаётся за сделанное

Анимации 120–180 ms (UI-07) по-прежнему отсутствуют — `motionMs` остаётся токеном без
применения; blur (UI-08) не рисуется; иконок нет (шрифтовые глифы не проверялись).
Внешний вид **не проверен ни одним запуском**: это чисто код отрисовки, скриншотов после
него нет. Синтаксис: 122/122 файлов разобраны парсером, компиляции не было.

## Раунд 7 — поддержка, диагностика старта, внешние интеграции (2026-11-12)

### 1. Отчёт об ошибке (`docs/support.md`)

Добавлен пользовательский сценарий «создать отчёт»: файл на рабочем столе
(`silkvis-report-ГГГГММДД-ЧЧММСС.txt`, до 512 КБ) с версиями, окружением, списком модов,
состояниями модулей, нашим ограниченным логом, хвостом `latest.log` и выборкой строк с
исключениями. Триггеры: кнопка в разделе «Настройки» и отдельный бинд (по умолчанию не
назначен). Запись на рабочий стол с фолбэком в `<gameDir>/silkvis-reports`.

Решения, которые стоит знать:

- читается только **хвост** лога (96 КБ с конца, 220 строк) — отчёт не может подвесить
  игру из-за гигабайтного лога;
- адрес сервера отдельным полем **не пишется**; предупреждение о том, что лог может его
  содержать, стоит в заголовке файла;
- содержимое наших JSON включается только если файл меньше 64 КБ;

## Раунд 8 — мигание виджетов и «побелка» панелей (2026-11-15)

### Симптом

Сообщение владельца: «виджеты обновляются с огромной частотой и на секунду то уходят то
приходят». На скриншотах это видно как два разных кадра: то только полоска FPS и
миникарта, то координаты, измерение, направление, биом и время — и всё это с наложением
панелей друг на друга.

### Причина 1 — модель HUD пересобиралась с нуля каждый тик

`HudDataCollector.tick` создавал новый `EnumMap` и складывал в него только те секции,
которые обновились на этом тике:

```java
Map<HudWidgetId, List<String>> lines = new EnumMap<>(HudWidgetId.class);   // было
if (positionLimiter.tryAcquire()) { lines.put(COORDINATES, …); }           // 10 Гц -> 1 тик из 2
lines.put(FPS, …);                                                          // каждый тик
if (fallbackLimiter.tryAcquire()) { lines.put(EFFECTS, …); }                // 1 Гц -> 1 тик из 20
```

`HudOverlayRenderer` пропускает виджет, если для него нет строк. Отсюда ровно то, что
описал владелец: координаты мигают на 10 Гц, эффекты/броня/инструмент «появляются на
секунду и исчезают» на остальные 19 тиков.

**Исправлено**: секции складываются в постоянный кэш (`cached`), а модель собирается как
его копия. Частоты обновления не изменились — изменилось только то, что последнее
известное значение не выбрасывается.

### Причина 2 — панели стали светло-серыми

В раунде 6 границы панелей рисовались как `theme.border().withAlpha(0.45f)`.
`border()` — это **белый с alpha 0.10**; `withAlpha(0.45f)` не ослабляет, а **заменяет**
альфу, то есть заливка «границы» стала белой на 45 %. `roundPanel` рисует границу
заливкой под полупрозрачной внутренней областью, поэтому каждый светлый прямоугольник
под панелью давал серую панель. Заменено на `theme.border()` (в одном месте —
`multiplyAlpha(0.6f)`).

### Причина 3 — выбранная вкладка стала сплошной бирюзовой плашкой

`ButtonWidget` рисовал границу и заливку **одним и тем же прямоугольником**: полупрозрачная
PRIMARY-заливка (accent 22 %) ложилась поверх непрозрачной accent-границы, и в сумме
получался чистый accent. Теперь граница — внешний прямоугольник, заливка — он же `inset(1,1)`.

### Причина 4 — панели налезали друг на друга

Смещения по умолчанию (6/24/42/60) были рассчитаны на однострочные панели, а координаты
занимают две строки. На скриншоте «Overworld» печатается поверх строки FPS.

Сделано два независимых исправления, потому что у владельца уже сохранён старый
`hud.json` и новые значения по умолчанию к нему не применятся:

1. новые смещения по умолчанию: 6 / 34 / 52 / 70, миникарта — 90;
2. в рендерере — проход сверху вниз с разведением: если прямоугольник виджета пересекает
   уже размещённый, он сдвигается ниже (`avoidOverlap`, не более 8 попыток, при выходе за
   экран возвращается исходный прямоугольник). Это чинит и уже сохранённые раскладки.

Из-за разведения порядок отрисовки теперь определяется `offsetY`, а `zIndex` — только
тай-брейкером: при отсутствии пересечений порядок слоёв больше не важен.

### Статус

Код исправлен, синтаксис проверен (126/126 файлов). **В игре не проверялось**: ни
отсутствие мигания, ни цвет панелей, ни отсутствие наложений ещё никто не видел.

## Раунд 9 — миникарта начала строить тайлы (2026-11-16)

### Причина, почему карта всегда была пустой

Семплер (`ClientTileSampler`) написан и привязан к `MapService`, бюджет 1 мс/тик работает,
`MapService.tick()` вызывается каждый тик. Не было одного звена: **никто не помечал тайлы
как требующие построения**. `markDirty` вызывался только из `MapService.markDirty` для
внутренних нужд, а рендерер по контракту только читает кэш. Итог — вечный
«Нет тайлов», хотя весь конвейер на месте. Это второй случай в проекте после
`HudDataCollector.onFrame()`: **написанный, но ниоткуда не вызванный код**.

### Что сделано

1. `client/MinimapPrefetcher` — раз в 10 тиков (2 Гц) берёт `MinimapView.visibleTiles(identity)`
   для текущей позиции и того же размера, что использует рендерер, и помечает как dirty
   только те тайлы, которых нет в кэше (не более 16 за проход). Стоящий на месте игрок не
   тратит ничего: кэшированные тайлы не запрашиваются повторно.
2. `MinimapRenderer` — выходные ячейки теперь раскладываются пропорционально: 48×48
   квадратов заполняют всё поле, раньше справа и снизу оставалась полоса пустой панели.
   Координаты блока для ячейки тоже считаются пропорционально, поэтому масштаб совпадает
   с `MinimapView`, а не «примерно».
3. `ui/widget/DynamicTextWidget` — строка с динамическим текстом (опрос не чаще 4 раз в
   секунду, исключения превращаются в текст, а не в краш рендера).
4. Вкладка «Карта» показывает живую диагностику `MapService.describe()`: сколько заданий в
   очереди, сколько тайлов в кэше, байты, hit-rate. Это ровно то, чего не хватало, чтобы
   отличить «не работает» от «ещё строится».

### Чего по-прежнему нет

GPU-текстуры тайлов (рисуем квадами из кэша — работает, но это дороже), полноэкранной
карты, слоёв Slice, маркеров и waypoint-ов, загрузки тайлов с диска по требованию (после
перезапуска тайлы строятся заново). Проверки в игре не было: 128/128 файлов разобраны
парсером, компиляции нет.

## Раунд 11 — анимации 140 мс и «Меньше движения» (2026-11-16)

### Что сделано

`ui/Animation` — один способ анимировать: `Fade` (плавное приближение к цели за
`theme.motionMs()`), `progress` (одноразовый переход для fade-in) и `mix` (смешивание
ARGB вместе с альфой). Время берётся из `System.nanoTime()`, а не из дельты кадра:

дельту через интерфейс `Widget` пришлось бы во все.

Применено:

- кнопки — фон/акцент между обычным и наведённым состоянием;
- тумблер — цвет дорожки и **положение ручки** по одной и той же кривой, поэтому они не
  расходятся; подсветка строки появляется плавно, а не «щелчком»;
- подложка главного окна и карты — fade-in по smoothstep. Панели при этом появляются
  сразу: полупрозрачная панель, выезжающая из нуля, читается как глюк отрисовки.

### «Меньше движения»

Длительность всегда берётся из темы. `SilkVisRuntime.applyTheme()` уже подменял
`motionMs` на 0 при включённой опции — теперь это действительно используется, и
уменьшение движения не требует отдельной ветки: `Fade` при нулевой длительности
фиксируется на цели в первом кадре.

## Раунд 12 — прокрутка настроек и интеграция AtlasMap (2026-11-16)

### 1. Колесо мыши в меню не работало — найдено и исправлено

Причина не в обработчике событий, а в модели прокрутки:

```java
private final ScrollModel listScroll    = new ScrollModel(0, 24);   // viewport = 0
private final ScrollModel settingsScroll = new ScrollModel(0, 28);  // viewport = 0
```

`ScrollModel` запоминает высоту видимой области **в конструкторе**. У обеих панелей она
была нулевой, `maxOffset()` при этом равен всей высоте содержимого — то есть список
модулей мог прокручиваться за собственный конец, а панель настроек не могла прокручиваться
вообще, потому что её высоту содержимого никто не выставлял, а `rebuildSettings()`
размещал контролы с абсолютным `y` без учёта `offset()`. Контролы просто уходили под обрез
панели.

Исправлено: обе модели пересоздаются в `init()` с реальной высотой видимой области,
`rebuildSettings()` начинается с `contentTop - settingsScroll.offset()` и в конце
регистрирует настоящую высоту содержимого, колесо над панелью настроек прокручивает и
перестраивает раскладку, при смене вкладки смещение сбрасывается. Добавлена полоса
прокрутки — без неё не видно, что ниже есть ещё контролы.

### 2. Карта — интеграция AtlasMap вместо своей (ADR-0007)

Владелец: «про карту давай забудем, сделаем интеграцию вот этой миникарты». Проверено по
исходникам `byMr712/AtlasMapExtended-MinecraftMod`: Fabric, `environment: client`, ветка

## Раунд 13 — музыка: появился бэкенд (2026-11-16)

### Диагноз до правок

Медиа-конвейер был написан целиком и никогда не имел входа: в репозитории не было ни
`silkvis-media-helper.exe`, ни `manifest.properties`, поэтому `MediaHelperBinary.verify()`
возвращал `helper_missing`, провайдер уходил в `ERROR`, а виджет Now Playing молчал при
любой конфигурации. Третий случай одного класса: `HudDataCollector.onFrame()`, префетчер
тайлов, теперь медиа — готовый конвейер без входного звена.

### Что сделано

1. **`silkvis-media-helper.ps1`** — мост к Windows GSMTC через WinRT без компиляции:
   сессии, метаданные, `PlaybackStatus`, таймлайн с seek-границами, capabilities из
   `Controls`, команды `PLAY/PAUSE/TOGGLE/NEXT/PREVIOUS/SEEK`, обложка как PNG base64.
   Есть режим `-Probe` — один снимок в консоль для проверки машины без сборки мода.
2. **Ленивый протокол**: скрипт не может тикать таймером, пока ждёт stdin, поэтому
   `WindowsMediaProvider` раз в 500 мс отправляет новый `SNAPSHOT_REQUEST`, а скрипт
   отвечает `SESSIONS` + `SNAPSHOT`. Нативный helper этот тип игнорирует.
3. **`MediaHelperLauncher`** — выбор бэкенда: `ExeHelperLauncher` (если `.exe` совпал с
   манифестом) → `PowerShellHelperLauncher` → отказ с причиной. Скрипт извлекается в
   `silkvis-data/native/media-helper-1` и проверяется по SHA-256 до запуска.
4. **Вкладка «Музыка»** показывает строку `Источник: …` — статус провайдера и причину
   отказа (`powershell_missing`, `hash_mismatch`, `gsmtc_unavailable`), а не пустоту.
5. `docs/media-helper.md` — ручная проверка одной командой до сборки мода.

### Ограничения, которые надо помнить

- Задержка обновления 500 мс (поллинг), старт скрипта 0.3–1 с, ~50 МБ на процесс.
- Кнопки управления в HUD и варианты отображения Now Playing **не сделаны** — это
  следующий раунд, и он требует загрузки PNG в текстуру.
- Обложки: JPEG-поток честно отбрасывается, отдаётся только PNG.

## 0.1.14-p0 — «хеш скрипта не совпал с манифестом», миникарта убрана

Первый реальный запуск `0.1.13-p1`: броня рисуется иконками (четыре строки, прочность,
полосы — как задумано), а музыкальный мост отказал с причиной
**«недоступно · хеш скрипта не совпал с манифестом»**. Причина видна именно потому, что
причина теперь печатается, — до 0.1.13 на этом месте была тишина.

### Почему хеш не совпал (это не «антивирус» и не PowerShell)

`sha256` в манифесте посчитан по файлу с переводами строк **LF**. На Windows-клоне с
`core.autocrlf=true` git отдаёт тот же файл с **CRLF**: содержимое то же, байты другие,
SHA-256 другой → `hash_mismatch` → провайдер не запускается. В Linux-среде, где собирался
манифест, этого не видно вообще.

| Правка | Что делает |
|---|---|
| `PowerShellHelperLauncher.normalizeLineEndings` | перед хешированием и перед записью извлечённого скрипта CR убирается; CRC-эквивалентность содержимого сохраняется, хеш сходится при любом варианте checkout |
| проверка упакованного ресурса при извлечении | если скрипт из jar не совпадает с манифестом, он не пишется на диск и не запускается (`packaged script hash mismatch`) |
| `.gitattributes` | `*.ps1`, `*.properties`, `*.json`, `*.java` → `eol=lf`; `*.bat` → `crlf`; новые клоны сразу байт-в-байт |
| `MediaHelperBinary.sha256(byte[])` | хеш по памяти, без временных файлов |

Бинарный путь (`media-helper.exe`) не нормализуется: там байты значимы.

### Миникарта

Владелец: «бери нашу миникарту, оставь только ту которую мы скачали». Своя миникарта
удалена, а не спрятана:

- `client/MinimapRenderer.java` удалён;
- `HudWidgetId.MINIMAP` остался в enum только ради старых `hud.json` — `available()` = false,
  по умолчанию `enabled=false`, рендер и редактор его пропускают;
- `HudLayoutConfig.decode` теперь **выбрасывает** неизвестный/удалённый виджет и
  продолжает разбор, а не падает: иначе у всех, кто когда-то включал миникарту, сбросилась
  бы вся раскладка HUD;
- полноэкранная карта SilkVis (`MapScreen`) и пауза тайлового конвейера при установленном
  AtlasMap остались без изменений.

### Остатки английского в HUD (найдены на скриншоте)

| Было | Стало |
|---|---|
| `Overworld` под координатами | «Обычный мир» — коллектор берёт имя измерения у рантайма (`silkvis.dimension.*`) |

Коллектор получает `Localizer` и функцию измерения в конструкторе; переключение языка
подхватывается со следующего обновления строк без перезапуска.

### Статус

`parsed=139 failed=0`. В игре не проверялось: запуск моста после нормализации концов строк,
отсутствие миникарты, русские измерения/стороны света.

### 0.1.14-p0 не собралась: исправлено в 0.1.14-p1

`SilkVisClient.java:49: incompatible types: invalid method reference` — `runtime::localizer`

## 0.1.14-p2 — краш `ClassNotFoundException: silkvis.client.SilkVisClient`

Сборка прошла, игра упала на `Initializing game`. В отчёте о краше два признака:

В `mods` лежал **sources-jar**, а не мод. `withSourcesJar()` публиковал второй файл

|---|---|
| `withSourcesJar()` убран из `build.gradle` | в `build\libs` должен оставаться один файл — ошибиться при копировании нечем |
| `build.bat` ставит jar сам | удаляет `silkvis-*.jar` из `%appdata%\.minecraft\mods` и копирует собранный; `-sources` отфильтрован, имя установленного файла печатается |
| `docs/build.md` | раздел «какой файл кидать в mods» |

Версия `0.1.14-p2`, чтобы отличить от сборки, которая лежала в `mods` рядом с sources-jar.

## 0.1.15-p0 — музыка заработала, дальше обложки, время, управление, редактор HUD

Первый запуск, где карточка Now Playing вообще появилась (название, исполнитель, источник

| Жалоба | Причина в коде |
|---|---|
| «проблема с отображением времени» | при неизвестной позиции рендер печатал `0:00` вместо «нет данных», а расшифровка состояния зависела от того, что пришлёт мост; не было ни одной строки, по которой это можно проверить |
| «не могу переключать треки, ставить на паузу» | кнопки существуют только на HUD-карточке в режиме взаимодействия, а клавиша этого режима по умолчанию **не назначена** (осознанно — чтобы не занимать чужие биндинги). Дойти до кнопок было нечем |
| «режим редактора худ работает очень плохо, не редактируется ничего» | редактор раскладывал все виджеты в условные прямоугольники 110×22 и при отпускании считал смещение по этой чужой ширине: виджет «прыгал» сразу после закрытия редактора. Плюс `setHudLayout` на каждое движение мыши писал файл (без debounce) |
| «пресеты не сохр.» | `VisualPreset` сохранялся, печатался в футере и **не влиял ни на что**: `applyTheme()` его не читал |
| «обложки не видны» | `MediaService.requestArtworkIfNeeded()` существовал и не вызывался **никем**; плюс скрипт отбрасывал миниатюры, если это не PNG, а Chrome и Spotify отдают JPEG |

### Что сделано

**Обложки.** `MediaService.tick()` теперь запрашивает миниатюру, повторяет запрос раз в 2 с,
пока её нет, и сбрасывает кэш при смене трека в той же сессии (ref миниатюры у WinRT —
на сессию, картинка — на трек). `ArtworkCache.looksLikeImage` принимает PNG/JPEG/GIF/BMP
(декодер — `ImageIO`), скрипт отправляет JPEG тоже; манифест скрипта пересчитан.

**Время.** Если источник не сообщает позицию, рисуется `--:--`, а не выдуманный `0:00`;
`LIVE` переводится (в русском — «прямой эфир»); вкладка «Музыка» показывает строку
«название — исполнитель · состояние   позиция / длина», чтобы состояние было видно без логов.

**Управление.** На вкладке «Музыка» появились «Назад / Пауза / Далее» — они работают из меню,
без режима взаимодействия. В «Настройках» — кнопка «Взаимодействие с HUD», которая включает
режим и сразу закрывает меню в него (клики по карточке). Клавиша по-прежнему не назначена.

**Редактор HUD.** HUD продолжает рисоваться под редактором и публикует реальные
прямоугольники (`HudOverlayRenderer.lastRects()`); редактор перетаскивает именно их, считает
смещение по настоящей ширине и пишет раскладку на каждом движении (сохранение — с debounce
500 мс, отдельный `uiDebouncer`). В меню/до входа в мир правки идут в общий профиль
`defaults` и наследуются новым профилем при первом входе — раньше при `profileId == null`
они просто терялись.

**Пресеты.** `LOW` / `BALANCED` / `QUALITY` теперь меняют плотность темы (радиусы и отступы)
через `ThemeTokens.withDensity`; `reducedMotion` — через `withMotion(0)`.

## 0.1.16-p0 — свой тотем бессмертия (ASSET-04, первое из V4)

Запрос: «вот работа над кастом тотемами, посмотри, улучши и залей». Во вложениях кода
тотемов **не было** — только шаблонные конфиги другого воркспейса (`AGENTS.md` от App
Builder, `eslint.config.mjs`, prettier, package-lock) и старые скриншоты SilkVis. Владелец
выбрал вариант «сделай тотемы в SilkVis», и фича реализована с нуля.

### Как это работает

1. Игрок кладёт картинку в `silkvis-data/totems/` (PNG или JPG).
2. Вкладка **«Тотемы»** перечисляет найденные файлы кнопками (до 8, отсортированы, мусор и
   папки отброшены).
3. Клик по имени → `assets/TotemPackBuilder` пишет настоящий набор ресурсов
   `resourcepacks/silkvis-totem/`: `pack.mcmeta` + `assets/minecraft/textures/item/totem_of_undying.png` 16×16.
4. Игрок один раз включает «silkvis-totem» в «Настройки → Наборы ресурсов» — перезапуск игры не нужен; если набор уже был включён, F3+T перечитывает текстуры. Про «применяется само» не написано намеренно: клиент кэширует текстуры, и обещать мгновенную подмену без перезагрузки ресурсов было бы враньём.

### Почему набор ресурсов, а не подмена текстуры в рантайме

Клиентский мод без миксинов не может подменить текстуру предмета «на лету»: путь к текстуре
приходит из модели, которую читает ванильный менеджер ресурсов. Инъекция в него — миксин,
то есть класс риска «урони игру на обновлении 1.22». Набор ресурсов делает то же самое
средствами самой игры: его видно в списке, его можно выключить, и он не может уронить клиент.
Требование ТЗ «никаких жёстких системных изменений» соблюдено.

### Детали, которые важны для качества

| Что | Как |
|---|---|
| Пиксель-арт | если стороны кратны 16 — уменьшение nearest neighbour (без смазывания), иначе bilinear (фото не превращается в шум) |
| `pack.mcmeta` | `supported_formats` 1…999, чтобы набор не стал «несовместимым» при следующей смене формата ресурсов (1.21.9 её уже делала) |
| Лимиты | файл ≤ 4 МБ, сторона ≤ 4096 px — отказ с кодом причины, а не `OutOfMemoryError` |
| Поток | сборка в IO-пуле: декодирование 4 МБ JPEG не может задержать кадр |
| Ошибки | коды (`file_missing`, `image_unreadable`, `write_failed`, …) переводятся в текст на вкладке, в лог пишется `TOTEM_PACK <файл>:<результат>` |
| Язык | все строки в `ru_ru`/`en_us` (247 ключей, наборы совпадают) |

### Проверки

Добавлены два self-check: сборка набора (размер текстуры 16×16, наличие `supported_formats`,
отказ на мусоре и отсутствующем файле) и листинг папки (сортировка, отброс `.txt` и папок,
лимит 8). `parsed=138 failed=0`.

## 0.1.17-p0 — тотем по ссылке (ASSET-04, продолжение)

Запрос: «сделай возможность добавлять по юрл». К вкладке «Тотемы» добавлено поле ссылки:
игрок вставляет адрес картинки, нажимает «Скачать и применить» — SilkVis скачивает файл в
`silkvis-data/totems`, сразу собирает набор ресурсов и показывает его в списке.

### Что именно проверяется у ссылки

| Правило | Зачем |
|---|---|
| только `http` и `https` | `file:` / `jar:` превратили бы текстовое поле в чтение локальных файлов |
| длина ≤ 512 | поле ввода с ограничением, и мусор в логе не растёт без предела |
| таймаут соединения и запроса 20 с | сервер, который «думает», не должен замораживать поток |
| тело ≤ 8 МБ, поток читается с обрывом | ссылка на 200 МБ не съест память: читаем кусками и обрываем |
| имя файла очищается (`[a-z0-9-_]`, до 48 символов) | никаких `../`, юникода и `con.png` из Windows |
| занятое имя → `-2`, `-3` | скачивание не перезаписывает прошлые картинки |
| папка заполнена (8 файлов) | честный отказ вместо девятого файла, которого не видно в списке |
| байты проверяет `TotemPackBuilder` | ссылка на HTML-страницу даёт «это не картинка», а не битый набор |

Скачивание идёт в IO-пуле (`executors.io()`), кадр не задерживается. Ссылка на HTML-страницу
или битый файл: файл, созданный самим модом, удаляется, в лог пишется `TOTEM_URL <причина>`,
на вкладке — русский текст причины.

### Мелочи, без которых «добавить по ссылке» бесполезно

- **Вставка из буфера** (Ctrl+V) — в самописной модели поля её не было, и длинную ссылку
  пришлось бы набирать руками. Теперь экран сам вставляет клиентский буфер в поле.
- Поле помечается рамкой ошибки, пока адрес не подходит (`ftp://`, просто слово), и не
  отправляет запрос зря.
- Вкладка перестраивается, когда фоновая задача закончилась: новый файл появляется в списке
  без переоткрытия меню (счётчик `totemVersion`, проверка в начале кадра).
- Черновик ссылки живёт в рантайме, поэтому прокрутка колесом (она пересобирает вкладку) не
  стирает набранный адрес.

### Проверки

Четыре новых self-check: правила ссылки (http/https, отказ `file:`, `ftp:`, `javascript:`,
пустой хост, слишком длинная), имя файла (декодирование `%20`, расширение из content-type,
запасное `totem.png`, ограничение длины), защита от перезаписи (`cat-2`, `cat-3`) и обрыв
скачивания сверх лимита. `parsed=141 failed=0`.

## 0.1.18-p0 — набор применяется сам, обложка доходит до экрана

Два отчёта владельца: «обложка треков не загружается» и «ресурс паки не работают, да он их
создаёт куда то, но не приминият».

### Набор ресурсов: писался, но не включался

`resourcepacks/` Minecraft читает **один раз при запуске**. Набор, созданный во время игры,
физически лежал на диске, но в списке «Наборы ресурсов» его не было вообще — включить было
нечего. Это не ошибка записи, а порядок работы игры.

Теперь после успешной сборки `client/TotemPackApplier` на потоке рендера делает ровно то,
что делает экран наборов при нажатии «Готово»:

1. `ResourcePackManager.scanPacks()` — перечитывает папку, набор появляется в профилях;
2. `setEnabledProfiles(… + "file/silkvis-totem")` — включает его;
3. `options.resourcePacks` синхронизируется, `options.write()` сохраняет выбор;
4. `reloadResourcesConcurrently()` — текстура применяется без перезапуска.

На вкладке «Тотемы» появились строка состояния («набор включён / выключен»), кнопки
«Включить набор» и «Выключить» и результат последнего действия словами. «Выключить» —
обязательная часть обратимости: ванильная текстура возвращается.

API намеренно узкий: `getResourcePackManager`, `scanPacks`, `setEnabledProfiles`,
`options.resourcePacks`, `options.write`, `reloadResourcesConcurrently` — это те же вызовы,
которые делает ванильный экран наборов. Если запись пуста, первым добавляется `vanilla`,
иначе набор из одной папки оставил бы игру без ванильных текстур. Любая ошибка ловится
(`Throwable`) и превращается в код, который вкладка показывает по-русски.

### Обложка: помощник выбрасывал JPEG

Причина найдена в `silkvis-media-helper.ps1`:

```powershell
# было
if ($size -gt 8 -and $buffer[0] -eq 0x89 -and $buffer[1] -eq 0x50) { ... }
```

Скрипт пересылал в мод **только PNG**, а Spotify и Chrome отдают обложку в JPEG — картинка
отбрасывалась каждый раз, и HUD честно рисовал заглушку. Вдобавок `DataReader.LoadAsync`
читался одним вызовом: он может вернуть меньше запрошенного, и поток обрезался.

Исправлено в помощнике:

- читаем в цикле, пока не набрано ровно `Size` байт (ограничение сверху — 512 КБ);
- принимаем PNG, JPEG, GIF, BMP и отдаём `mime`;
- возвращаем `reason` (`no_thumbnail`, `empty_stream`, `too_large`, `not_an_image`,
  `open_failed`, `exception`) и число байт;
- освобождаем `DataReader` и поток.

На стороне Java: причина сохраняется в `MediaService.artworkNotice()` и показывается в
вкладке «Музыка» строкой «Обложка загружена / жду ответа / не пришла: <причина>». Раньше
пустая обложка не оставляла вообще никакого следа. В stderr-хвост помощника пишется
`artwork: <причина>` — это попадает в отчёт об ошибке.

### Проверки

картинкой, JPEG принимается (тот самый случай), мусор получает `not_an_image`.
`parsed=142 failed=0`. Манифест помощника пересчитан (sha256 в `media-helper.properties`),
