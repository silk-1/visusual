# Отчёт об ошибке (bug report)

## Как получить

Два способа, оба делают одно и то же:

1. **Экран SilkVis → «Настройки» → «Создать отчёт об ошибке».**
2. Клавиша `key.silkvis.bug_report` — по умолчанию **не назначена** (чтобы не занимать
   чужие бинды), назначается в «Управление → SilkVis».

После создания в чат приходит строка `Отчёт SilkVis сохранён: <путь>`.

## Куда пишется

Сначала на **рабочий стол** пользователя. Проверяются варианты `Desktop`,
`Рабочий стол`, `OneDrive\Desktop`, `OneDrive\Рабочий стол` (Windows часто переносит
рабочий стол в OneDrive). Если ни один не найден или запись не удалась — файл падает в
`<папка игры>\silkvis-reports\`. Имя: `silkvis-report-ГГГГММДД-ЧЧММСС.txt`.

## Что внутри

| Раздел | Содержимое |
|---|---|
| заголовок | версия SilkVis, версия Minecraft, время создания, предупреждение о содержимом |
| System | ОС, Java/JVM, число ядер, max/allocated heap, uptime JVM, строка GPU (vendor/renderer/GL) |
| SilkVis | тема, язык, пресет, reduced motion, blur, профиль (только `kind`), очереди IO, наличие media/map, сколько HUD-виджетов включено, измерение карты |
| Game | размер окна, GUI scale factor, render distance, FPS, в мире/вне мира, одиночная ли игра |
| Mods | список `id версия` всех модов, отсортированный, до 300 строк |
| Modules | каждый модуль: `id | состояние | available | reason | detail` |
| Integrations | sodium / iris / baritone / hud_hook: наличие и причина отказа, режим шейдеров |
| Config files | пути, размер, и содержимое наших JSON, если файл меньше 64 КБ |
| SilkVis diagnostics log | ограниченный лог самого мода (код события + деталь, число повторов) |
| Errors in latest.log | строки с `Exception`, `Caused by:`, `ERROR`, `[SilkVis]` из хвоста лога |
| latest.log tail | последние 220 строк (читается максимум 96 КБ с конца файла) |

## Приватность

- **Адрес сервера не пишется** отдельным полем: `serverAddressIncluded: false`.
  Но хвост `latest.log` может содержать адрес, если ты заходил на сервер — в заголовке
  файла это сказано прямо; перед отправкой можно вырезать нужные строки.
- Имя аккаунта в отчёт не попадает целенаправленно.
- Ничего никуда не отправляется автоматически: файл создаётся локально, решение
  отправлять его — твоё.
- Метаданные треков в отчёт не попадают (правило MEDIA-17): в лог пишутся только коды
  событий, не названия песен.

## Ограничения

- Отчёт не перехватывает краши JVM: если игра уже упала, файла не будет. Тогда нужен
  `crash-reports\` из папки игры — он создаётся самим Minecraft.
- Размер ограничен 512 КБ; при превышении в конце появляется строка
  `[report truncated at …]`.
- GPU-строка читается из текущего GL-контекста: на некоторых драйверах вернётся
  `unavailable (...)` — это нормально, отчёт не из-за этого становится бесполезным.
