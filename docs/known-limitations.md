# Известные ограничения SilkVis

Дата: 2026-11-12. Снимок `main@e87b2084089a898844aafe4eeeb86ecdbfca73cb`.
**P0/V0 не принят: успешная сборка и игровой запуск не подтверждены.**
Актуальные команды и исторические логи разделены в [status-report.md](status-report.md).

## Действующие блокеры

1. **Сборка не подтверждена.** На предыдущем снимке `0c2d7e6` единственная попытка
   `bash gradlew clean build` завершилась exit 1 при скачивании Gradle 9.8.2:
   `java.net.SocketException: Network is unreachable`. Gradle не запустился;
   блока `* What went wrong:` нет. Это bootstrap/сеть вне четырёх категорий §4,
   не доказательство несовместимости версий. На `e87b208` build не повторялся,
   поскольку изменение сетевых условий не подтверждено. Пункт снимается только
   после успешного build + selfCheck. В среде агента Java 21 runtime есть,
   `javac` не найден. Доступа к Windows-ПК владельца нет.
2. **ASCII-гейт не пройден на актуальной базе.** Свежая команда
   `python scripts/verify.py` вернула exit 1: не-ASCII в 10 из 122 Java-файлов,
   20 строк. Паритет lang-ключей: 118/118, 0 расхождений.
3. **PowerShell-проверка не выполнена.** `verify.ps1` создан, но `pwsh` и
   `powershell` отсутствуют; предыдущая попытка запуска завершилась shell exit 127.
   Независимая Python-проверка не заменяет исполнение этого скрипта.
4. **selfCheck и клиент не запускались.** До зелёного build-гейта переход дальше
   остановлен. Нет игрового evidence для UI/HUD/карты или screenshots.
5. **Музыкальный helper не поставлен готовым бинарником.** Код
   `MediaHelperBinary` содержит отказ `helper_missing`; runtime-поведение
   не проверено. Матрица источников и M-01…M-08 остаются NOT_TESTED.

Минимальное направление исправления: пользовательские названия брать из lang-ресурсов,
комментарии сделать ASCII; необходимые Unicode-символы/тестовые данные можно представить
Java Unicode escapes, сохранив проверяемое поведение. Само экранирование русских
пользовательских строк не исправляет отсутствие локализации.
Правки относятся к владельцу Java-кода; сторонние агенты не должны их вносить здесь.

## Сохраняющиеся пробелы P1

Перечень унаследован из предыдущего отчёта и сопоставлен с именами файлов.
Это не новая игровая проверка; статус выполнения перечисленных сценариев — NOT_TESTED.

- Карта: `MinimapRenderer` использует 48×48 квадов; GPU texture path, полноэкранная
  карта, полный CRUD/приёмка точек не подтверждены. В AGENTS.md §5 зафиксирована
  прежняя сверка API сэмплера — повторно объявлять сигнатуры непроверенными по
  исходникам не следует, но успешной компиляции всё ещё нет.
- HUD: применение per-widget scale, lock/z-order/resize, hit-testing музыкальных
  кнопок и восстановление курсора не приняты. Drag/snap/guides присутствуют в
  исходниках редактора, но «работают» без запуска утверждать нельзя.
- UI: blur-effect, избранное/изменённые настройки, полноценные color/keybind/file
  picker/modal/toast controls и проверка RU/EN на экране не завершены/не приняты.
- ASSET-01…04: загрузка PNG/JPEG/HTTP, custom sky и тотем остаются планом V4.
- VIS-01…03: наличие настроек не означает применения FOV/тумана/частиц; hooks и
  совместимость должны подтверждаться отдельно, без добавления mixins в этой задаче.
- `TileSampler` использует компромисс 2×2 sampling; PERF-01…05, кэши, SOAK и
  vanilla/Sodium/Iris/shader matrix не измерялись.
- Паритет lang-ключей подтверждён: по 118 в каждом файле, 0 расхождений.
  Это не закрывает UI-09 целиком: перевод, plural forms, glyphs и hardcoded строки
  требуют отдельных проверок.

## Ограничения проверки и P2

`scripts/verify.ps1` — только статические проверки ключей/байтов. Он не компилирует
Java и не проверяет ссылки на классы, API или поведение Minecraft.
`scripts/verify.py` не подтверждает исполнение PowerShell; 12 успешных fixture-сценариев
относятся только к Python в этой среде.

`selfCheck` объявлен в Gradle как JavaExec с зависимостью `testClasses`.
Отсутствие JUnit не устраняет необходимость Gradle resolve и компиляции в чистой среде.

Автоматизация A01…A22 остаётся PLANNED до принятого V5. Новая функциональность P1/P2
в этой работе не добавлялась. Неуспешный bootstrap, непроверенная конфигурация и отсутствие
клиентской приёмки нельзя подменять статусом «готово с ограничениями».
